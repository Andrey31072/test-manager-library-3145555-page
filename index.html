Manager Library

A small-library operations system built from a spec-first reading of the product rules, API contract, and data model.

Operational Scope

Catalog

Active books, fixed categories, optional covers, ISBN uniqueness, and logical deletion.

Members

Member records with unique document numbers. Members are data, not login users.

Loans

One to three books, 14-day due dates, frozen item values, one-line returns, and calculated status.

Reports

Most-borrowed aggregation grouped by frozen book title and category, without exposing members.

Six Repositories

The project is intentionally split across docs, API, app, page, infra, and tool repositories. Each repository has a narrow responsibility and evidence path.

  1. Docs: English SDD adaptation before code.
  2. API: Laravel contract and business rules.
  3. App: React operational workflow.
  4. Page: public static presentation.
  5. Infra: empty PostgreSQL engine and containers.
  6. Tool: API-only demo seeder.

Boundaries Kept

No fines, payments, reservations, renewals, email, bulk imports, branches, publisher/year/language fields, audit columns, report tables, or member login were added.
